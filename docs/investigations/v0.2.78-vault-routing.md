### Bug A — `.bak.*` directories scanned as libraries

`_detect_library_vaults` (snippet_registry.py:254-262):

```python
def _detect_library_vaults(self, vault_path: str) -> list:
  if not os.path.isdir(vault_path):
    return []
  out = []
  for entry in sorted(os.listdir(vault_path)):
    sub = os.path.join(vault_path, entry)
    if os.path.isdir(sub) and os.path.isfile(os.path.join(sub, _MANIFEST_FILENAME)):
      out.append(sub)
  return out
```

The filter is `os.path.isdir(sub) AND has forge.toml`. No exclusion for
`<base>.bak.<version>/` patterns. v0.2.38's auto-re-extract mechanism
renames the existing extracted library to `<lib>.bak.<oldver>/` before
copying the bundled fresh version in — the .bak retains its forge.toml,
satisfies the filter, and gets scanned.

**Two distinct symptoms** the test exposes:

1. **Collision on library name**. Both `forge-tutorial/forge.toml` and
   `forge-tutorial.bak.0.1.0/forge.toml` declare `name =
   "forge-tutorial"`. `_scan_library_vault` writes entries into
   `_vaults["forge-tutorial"]`; the second scan (.bak comes after fresh
   in `sorted(os.listdir(...))`) overwrites whatever the first scan
   stored under matching sub-path keys. Effect: depending on directory
   sort order, the user gets STALE snippet bodies from the .bak.

2. **Wrong snippet_id from plugin**. The plugin computes snippet_id
   from file path: clicking `forge-tutorial.bak.0.1.0/01-hello/hello_world.md`
   produces snippet_id `forge-tutorial.bak.0.1.0/01-hello/hello_world`.
   This vault name doesn't exist in `_vaults` → resolver raises
   `SnippetResolutionError`.

**Fix scope (Bug A)**: exclude `.bak.<version>/` directories from
`_detect_library_vaults`. Pattern detection via regex `\.bak\.` in the
directory name is the simplest, narrowest fix; matches the v0.2.38
rename convention exactly without coupling to a hard-coded library
allowlist.

### Bug B — `get_bare` misses library sub-path entries

`get_bare` (snippet_registry.py:181-187):

```python
def get_bare(self, bare_id: str) -> Optional[dict]:
  for vault_name in self._order:
    hit = self._vaults.get(vault_name, {}).get(bare_id)
    if hit is not None:
      return hit
  return None
```

Direct key lookup only. Library entries are stored under sub-path keys
(per `_scan_library_vault:208-209` which sets `bare_id =
os.path.relpath(filepath, lib_path).replace(os.sep, "/")` and strips
the .md extension). So a library snippet at `forge-music/blues/chorus.md`
is stored as `_vaults["forge-music"]["blues/chorus"]`. `get_bare("chorus")`
looks for `_vaults["forge-music"]["chorus"]` — not the actual key.
Misses.

**Effect on freeze**: pyodide-host.ts:628 `_forge_qualify_snippet_id`
calls `_forge_registry.get_bare(snippet_id)`. For bare wikilink targets
(e.g. `[[chorus]]` inside `forge-music/blues/song.md`), get_bare returns
None → qualify falls through unchanged → `set_snapshot_state` looks for
snapshot at `.forge/edges/chorus/song.md` which never existed. The
compute path captured the snapshot at the qualified path
`.forge/edges/forge-music/blues/song/forge-music/blues/chorus.md`.
FileNotFoundError on freeze.

**Fix scope (Bug B)**: extend `get_bare` to also search by basename
across sub-path keys when no direct-key match is found. Walk the
resolution order; for each vault, check direct keys first (preserving
authoring-vault top-level semantics), then scan all keys for any whose
last `/`-segment equals the bare_id. First match wins (resolution
order semantics preserved). The capture path uses
`snippet["snippet_id"]` which is always the correct qualified id, so
freeze just needs to find that same qualified id from the bare.

### Cross-cutting audit

Both bugs share the v0.2.75 architectural pattern: "default to AUTHORING
(or bare) for unknown vault membership." Per the prompt §2.3:

```
grep -rn "AUTHORING\|authoring/" forge/core/ src/pyodide-host.ts src/main.ts
```

Sites found and evaluated:
- `forge/core/snippet_registry.py` — AUTHORING_VAULT default in scan
  (correct: authoring is the vault root), refresh_file (v0.2.75 fixed),
  `_detect_library_vaults` (Bug A, this drain).
- `forge/core/snippet_registry.py` — `get_bare` walks `_order` which
  starts with AUTHORING (Bug B, this drain).
- `src/pyodide-host.ts:628` — `_forge_qualify_snippet_id` falls through
  to bare unchanged (Bug B downstream).
- `src/main.ts` — no AUTHORING-default sites in the editor toolbar
  paths (uses metadataCache + per-file frontmatter for type).

No additional buggy sites surfaced. Bugs A + B exhaust the known
"default to AUTHORING" defect pattern at this audit's depth.
